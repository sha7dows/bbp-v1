## 1. 问题锚点（冻结，后续所有轮次不得漂移）

- **底层问题**：现有超图存在"超边数量多、超图规模巨大"的结构性缺陷（Vine 上以 STC 超边为主），导致构图与 IBG/覆盖计算开销大、巨型与高度重叠超边稀释行为信号、剪枝在冗余集合上行为失真。
- **必须解决**：在 **不更换任务、不引入外部数据、不引入新超边类型、不改动三段式架构（超图构建 → IBG 高维多关系建模 → 多维融合）** 的前提下，从超图**结构的生成层面**压缩超边数量与规模，同时保持（目标：提升）检测性能。
- **非目标**：不做训练期数据增强式"绕开结构"的改动；不把"调 θ / retention 参数"当作结构创新；不改五折评测协议。
- **约束**：
  - 实验协议沿用现有 CV5 逻辑（固定 20% 最终测试 + 开发集五折 + 跨折选全局 epoch + 最终集成评估），**不照搬论文 80/20 五次随机协议**。
  - 一次实验只改一个机制；决策只用验证折；固定测试集只在配置锁定后评估一次；多 seed 42–46，`louvain_seed` 与训练 seed 同步。
  - 结构改动必须确定性、与标签无关（构图不读 y），同一超参对训练/验证/最终测试一致生效。
- **成功条件**：结构性指标显著改善（超边数/incidence/IBG 规模/单 epoch 时长下降）且分类指标（positive/macro F1、AUROC）不降、五折方差更稳，并形成可写进论文的"构图端压缩"叙事与消融。

## 2. 背景审阅

### 2.1 论文方法回顾（BeHM）

- 两类互补层次：**微观**＝用超边表示"协调群体行为"（STC 语义—时间协调、User 用户连贯、Mention 提及互动）；**宏观**＝把超边当行为节点建 Interaction Behavior Graph（IBG，Jaccard 边权）→ GAT 传播 → Louvain 社区。
- 融合：节点/超边/社区三级特征，全局社区上下文作 query 的注意力融合 + 残差；logit adjustment 缓解类别不平衡；annotator 一致性 confidence 加权 CE。
- 实验：Instagram / Vine 会话数据集，F1 0.796 / 0.716，AUC 0.907 / 0.845；超边分布（全文 Table II）：Vine STC=63389(91.71%)、User=5704(8.25%)、Ment=23(0.03%)；Instagram STC=137153(85.57%)、User=12922(8.06%)、Ment=10216(6.37%)。**规模主战场＝STC**。

### 2.3 现有五折协议确认（遵循，不改）

`train_vine_cv5.py` 的实现与你描述一致：
1. 按 `seed` 在全集做分层划分，取出固定 **20% 最终测试**；
2. 其余（train+validation 合并）作为开发集，按 `fold_seed` StratifiedKFold **五折**（每折 8:2 = 训练:验证）；
3. 五折共用同一训练 seed，保存每折逐 epoch 权重；
4. 跨折聚合每个 epoch 的验证指标：先最大化均值 → 再最小化 std → 再取更早 epoch（`select_global_epoch`）；
5. 配置锁定后（`--evaluate-final-test`）对固定测试集用五模型同 epoch 概率平均做一次最终评估（阈值 0.5）。

## 3. 规模问题的根因（代码级分析）

### 3.1 STC 以"节点为中心"生成 → O(n) 条、每条 O(n) 尺寸、天然嵌套链

`_build_stc` 对会话内每个节点做中心，凡 `fused[:, center] ≥ threshold` 的节点全部并入该中心超边（对角线=自身恒在边内）。特征归一化后 `fused` 近似对称 ⇒ 互相相似的两个中心各自生成"几乎同一簇"的边，产生**链式/嵌套冗余**（E(c) ⊂ E(c′) ⊂ E(c″)…）。构建端只在节点集合**完全相同**时合并（`bucket` key 去重），子集与近重复链保留。

### 3.2 巨型超边 → 下游系统性退化

Vine 文本碎片化 + BERT 特征在 θ≈0.6 下容易形成覆盖会话大半的巨边，引发：

- IBG 中巨边间 Jaccard≈1 ⇒ IBG 近完全图、权重无区分；
- Louvain 在近完全图上退化成少数巨型社区 ⇒ 社区特征趋零；
- 覆盖目标（`_representativeness_matrix`）中一条巨边即可顶满 coverage ⇒ 鲁棒自适应剪枝"一票达标"，保留率失真；
- HGNN/边 readout（默认 sum）与融合注意力被巨边主导。

### 3.3 计算量随保留边数近似二次放大

- IBG：每会话每前向做 `incidence @ incidence.t()`（O(E²)）+ 逐会话 Louvain（`backbone.build_ibg`、`forward_projected`）；
- selector 覆盖：每类型每会话 O(k²) 代表矩阵，鲁棒贪心每步重算 `_candidate_robust_progress_gains`（含 O(k²) topk），最坏 O(k²·max_keep)（`selector.py`）；
- 以上在**每个训练 epoch、每个 batch** 全量重算（`train_epoch`），E 变大 ⇒ 墙钟/显存近似线性–二次放大。

### 3.4 已有减负手段的缺口

| 手段 | 位置 | 性质 | 缺口 |
|---|---|---|---|
| `dedup_mode=subset` | 构图期 | 单条边"物理包含"剔除 | 不处理两(多)条边的并覆盖；Jaccard 可很小 |
| `dedup_mode=jaccard` | 构图期 | **两两** PK，保 strength 高者 | 链式冗余（A~B~C、A≁C）可全存活；无传递性 |
| BBP selector | 模型期 | 学习打分 + 预算/覆盖约束选边 | 事后减负；巨边顶满覆盖 ⇒ 行为失真；为冗余付训练代价 |
| IBG 边权软化/硬剪 | IBG 期 | 改边权形态 | 不改超边集合本身 |

**核心判断**：现有手段都是"事后/局部"减负，**没有在行为基生成层面回答"每会话最少且互不冗余的行为基是哪些、尺寸上限多少"**。这正是本提案的缺口与机会。

## 4. 方法设计

### 4.1 设计原则

1. **最小充分机制**：优先在构图函数内部做纯结构变换，不动模型/训练/IBG/协议；
2. **保证可解释与可审计**：每次删除都绑定一个"被删边可被保留边代表"的度量；每次切分都保持"成员全覆盖、零信息丢失"；
3. **向后兼容**：所有新开关默认关闭，默认行为 = 现行为；
4. **与 BBP selector 正交**：构图端压缩后 selector 仍可保留作最终精剪，二者可消融对比。

### 4.2 机制 A：STC"行为基"贪心覆盖归并（传递性去重）

**目标**：把 `jaccard` 模式的两两 PK 升级为**强度降序 + 已保留集合比较**，实现链式冗余的传递闭包删除，并使"被删边与某保留边 Jaccard ≥ τ"成为**构造性保证**。

**算法（在 `_dedup_stc_bucket` 内新增 `dedup_mode="cover"` 分支）**：

```
输入：会话内 STC 候选（members 元组 + construction_strengths）
1. 按 construction_strength 均值降序排序（并列 → 尺寸更大优先）
2. kept = []
   for key in 排序后的 keys:
       if ∃k ∈ kept 使 Jaccard(key, k) ≥ τ:   # 可被代表 → 删
           continue
       kept.append(key)                         # 否则成为新代表
3. 返回 {k: bucket[k] for k in kept}
```

**性质**：
- 被删边一定直接邻近某保留边（Jaccard ≥ τ），代表度有下限；
- 传递链 A~B~C（A≁C）中 A 保留、B 删、C 若与 A<τ 则保留——比两两 PK 更激进且不破坏代表下限；
- 复杂度每会话 O(m²·|members|)（m=会话 STC 候选数），远低于训练代价，可接受。

**参数**：复用 `dedup_jaccard_tau`（⚠ 具体取值在 dev 上选，参考现值 0.90 邻域做粗扫，见 §7）。

**待拍板**：subset 剔除是否与 cover 串联（子集包含的 Jaccard 可能很小，二者删除的冗余性质不同），默认建议**先单独测 cover**，用代表度审计决定是否加 subset 前置。

### 4.3 机制 B：超大 STC 边的时间连续性切分（尺寸上限）

**目标**：切断"巨边 ⇒ Jaccard/覆盖/社区退化"链路，同时不丢节点、不破坏"STC=时间连续协调行为"的语义。

**位置**：`_build_stc` 之后、去重之前（**先切分后去重**，顺序不可反——先归并会把应被切分保护的嵌套信息删掉）。

**算法（新函数 `_split_oversized_candidates(bucket, cap, gap)`）**：

```
for 每个尺寸 > cap 的 STC 候选:
    1. 成员按 create_time 升序排列
    2. 在相邻时间差 > gap 处断开 → 时间连续块（gap 由超参控制）
    3. 丢弃单成员块（不构成行为）；仍有块 > cap → 按时间连续切成 ≤ cap 的块
    4. 每个子块生成子候选：重算 construction_strength / time_span_days / unique_user_count
    5. 删除原候选
```

**性质**：
- 成员被**恰好一条**子边覆盖 ⇒ 覆盖零损失；
- 子边 = 时间连续的子行为基，语义与论文定义自洽；
- `cap`（如 dev 训练/验证 p90/p95 尺寸，⚠ 用训练折统计、不用测试）与 `gap` 为超参。

### 4.4 A+B 组合语义

管线：`build STC` →（可选 B）切分巨边 →（可选 A）cover 归并 → 产出 records。A 在尺寸受控的集合上做归并更干净（巨边切分后产生的嵌套子边会被 A 二次清理）。A、B 各自是**可独立开关**的单机制消融。

### 4.5 明确不做（防范围蔓延）

- 跨类型去重（User 边天然不相交；Mention 在 Vine 上仅 23 条；类型语义被 embedding/分类型覆盖依赖）；
- 把 θ/tau 的"扫参"当结构创新（仅作机制参数的常规选择）；
- 删除/替换 BBP selector（保留为与构图端改动的正交对比）。

## 7. 实验计划（遵循 CV5 协议）

实验矩阵（**一次一个机制**，全部用 `scripts/train_vine_cv5.py`，先不 `--evaluate-final-test`）：

| 组 | 配置 | 目的 |
|---|---|---|
| E0 | Vine 基线（§2.4 全表；dedup_mode=`subset`） | 基线（复现/对齐现状，须与运行目录配置一致） |
| E1 | 基线 + A cover（τ 按诊断选 1–2 档） | A 相对 subset 的增量效果 |
| E2 | 基线 + B（cap 按诊断 p95 档） | B 单独效果 |
| E3 | 基线 + A+B | 组合效果与交互 |
| E4（可选） | A 与 subset / jaccard 模式两两对比 | 定位"cover（传递性）"相对"subset/两两 PK"的增益 |

流程：每组的 **fold_validation 结构指标 + 验证 F1/AUROC** 决定是否推进；配置锁定后才评估固定测试集；多 seed 42–46 各自完整 CV5，最终报 mean±std。记录：`candidate_edges/kept/ibg_*/retention/coverage` + macro/positive F1、AUROC + 每 epoch 墙钟。

## 8. 风险与止损

| 风险 | 症状 | 止损/缓解 |
|---|---|---|
| τ 过小误删真实小群组 | 验证 F1/AUROC 掉、代表度审计差 | 提高 τ / 只留 subset 档 / 回退默认 |
| cap/gap 破坏围攻行为边界 | 验证掉点但结构数字"好看" | 以"指标不降"为硬门槛，不唯压缩率论 |
| 切分引入新超参方差 | 五折 std 变大 | dev 折选参；必要时只保留 A |
| 与 BBP 覆盖目标交互异常 | kept/coverage 分布突变 | 逐组看 stopping_reason/保留率直方图 |
